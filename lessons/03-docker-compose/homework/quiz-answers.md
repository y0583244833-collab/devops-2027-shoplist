# בוחן שיעור 3: <ריקי ילין>

1. ב

2. ג

3. Reverse proxy הוא שרת שמקבל בקשות מהלקוח, מעביר אותן לשרת המתאים ומחזיר ללקוח את התשובה.

4. ב

5. הבקשה מגיעה ל-backend בנתיב /products, כי הגדרת Nginx מסירה את התחילית /api/ לפני העברת הבקשה.

6. ה-backend נגיש ל-Nginx דרך הרשת הפנימית של Docker, ולכן אין צורך לפרסם לו פורט במחשב באמצעות ports.

7. docker compose down מסיר את הקונטיינרים והרשת אך שומר את ה-volumes, ואילו docker compose down -v מוחק גם את ה-volumes של הפרויקט ואת הנתונים שבהם.

8. ב

9. depends_on לבדו מבטיח סדר הפעלה, אך לא שמסד הנתונים מוכן לקבל חיבורים; כדי לחכות למוכנות מגדירים healthcheck ותנאי service_healthy.

10. ב

11. המיפוי הראשון הוא volume ש-Docker מנהל לשמירת נתוני המסד, והשני הוא bind mount שמחבר את קובץ init.sql מהמחשב לתוך הקונטיינר לצורך אתחול המסד.

12. ב

13. הפקודה docker compose config בודקת את תקינות הגדרות ה-Compose ומדווחת על שגיאות.

14. סיסמאות בקובץ עלולות להיחשף ב-GitHub, ולכן מעבירים אותן באמצעות משתני סביבה, למשל מקובץ .env שמוסיפים ל-.gitignore ולא מעלים למאגר.

15. Nginx מוגדר לפנות לשירותים אחרים בשמותיהם ברשת של Compose; בהרצה לבד הוא אינו מצליח לפתור את שמות השירותים לכתובות, ולכן נכשל בהפעלה.
